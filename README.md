# RAG HR Assistant

A Retrieval‑Augmented Generation (RAG) based HR assistant that answers employee questions using company policies stored in a remote text file. The system pulls the policy document from a GitHub raw URL, splits it into manageable chunks, stores the embeddings in a Chroma vector store, and uses a Groq LLM to generate answers grounded in the provided context.

## Features

- **Dynamic policy loading** – fetches a plain‑text HR policy file from a configurable GitHub raw URL.
- **Chunk‑based indexing** – splits the document into word‑based chunks (default 50 words) for efficient retrieval.
- **Vector store** – uses **Chroma** to store embeddings generated by the `all‑MiniLM‑L6‑v2` model.
- **Grounded generation** – leverages Groq's `openai/gpt-oss-safeguard-20b` model with a system prompt that forces the assistant to answer **only** from the supplied context.
- **Simple CLI** – run the ingestion pipeline and query interface from the command line.

## Architecture Overview

```
+----------------+      +----------------+      +----------------+
|   config.py    | ---> |  ingest.py     | ---> |  store.py      |
+----------------+      +----------------+      +----------------+
       |                       |                       |
       v                       v                       v
+----------------+      +----------------+      +----------------+
|  main.py       | ---> |  query.py      | <--- |  Chroma DB     |
+----------------+      +----------------+      +----------------+
```

- **config.py** – centralised configuration (GitHub URL, model names, chunk size, etc.).
- **ingest.py** – fetches the raw document, cleans it, and splits it into chunks.
- **store.py** – creates/loads the Chroma collection and adds embeddings.
- **query.py** – retrieves relevant chunks, constructs a prompt, and calls the Groq LLM.
- **main.py** – entry point that wires everything together.

## Setup

### Prerequisites

- Python **3.10** or newer.
- Access to the internet (to download the policy file and model weights).
- An API key for Groq (set as the environment variable `GROQ_API_KEY`).

### Installation

```bash
# Clone the repository
git clone https://github.com/your‑org/rag-hr-assistant.git
cd rag-hr-assistant

# Create a virtual environment (recommended)
python -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate

# Install dependencies
pip install -r rag/requirements.txt
```

### Configuration

All configurable values live in **`rag/config.py`**:

- `GITHUB_RAW_URL` – URL to the raw policy text file.
- `EMBEDDING_MODEL` – Sentence‑transformer model used for embeddings.
- `GROQ_MODEL` – Groq LLM identifier.
- `CHUNK_SIZE` – Number of words per chunk (default 50).
- `CHROMA_PATH` – Directory where the Chroma store persists.
- `SYSTEM_PROMPT` – Prompt that enforces grounded answers.

Update any of these values as needed before running the pipeline.

## Running the Application

### Ingesting Documents

```bash
python -m rag.main ingest
```

The command will:
1. Download the policy document from `GITHUB_RAW_URL`.
2. Split it into chunks using the size defined in `CHUNK_SIZE`.
3. Generate embeddings and store them in a Chroma collection located at `CHROMA_PATH`.

### Querying

```bash
python -m rag.main query "What is the company's vacation policy?"
```

The query script will:
1. Retrieve the most relevant chunks from the vector store.
2. Build a prompt that includes the system prompt and the retrieved context.
3. Call the Groq model to generate a concise answer.
