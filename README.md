# HR Document Retrieval Assistant (RAG)

A lightweight Retrieval‑Augmented Generation (RAG) application that ingests a plain‑text HR policy document from a public GitHub repository, stores it in a local **Chroma** vector store, and answers user questions using a **Groq** large language model. The tool is designed for developers who want a simple, end‑to‑end example of how to combine document chunking, embeddings, vector search, and LLM prompting.

## Overview

The repository contains a minimal RAG pipeline written in Python:

1. **Ingestion** – Download a raw text file from GitHub and split it into fixed‑size word chunks.
2. **Embedding** – Convert each chunk into a vector using the `all‑MiniLM‑L6‑v2` sentence‑transformer model.
3. **Vector Store** – Store the embeddings in a local **Chroma** collection for fast similarity search.
4. **Retrieval** – Given a user query, retrieve the most relevant chunks.
5. **Answer Generation** – Send the retrieved context and the query to a Groq LLM (`openai/gpt‑oss‑safeguard‑20b`) with a system prompt that forces the model to answer *only* from the supplied context.

The result is an interactive command‑line assistant that can answer HR‑related questions without hallucinating information beyond the provided policy document.

---

## Features

- **Zero‑setup document source** – The HR policy file is fetched directly from a public GitHub raw URL.
- **Chunk‑based retrieval** – Adjustable chunk size (default 50 words) for optimal balance between relevance and token limits.
- **Local persistence** – Chroma stores embeddings on disk (`./chroma_store`) so you don’t need to re‑ingest on every run.
- **Safety‑first prompting** – System prompt instructs the model to never fabricate answers.
- **Simple CLI** – Interactive loop with graceful exit commands (`quit`, `exit`, `q`).

## Setup

### Prerequisites

- Python **3.10** or newer
- Git (to clone the repository)
- An API key for **Groq** (free tier available at https://groq.com)

### Installation

```bash
# 1. Clone the repository
git clone https://github.com/tnahddisttud/sample-doc.git
cd sample-doc

# 2. Create a virtual environment (optional but recommended)
python -m venv .venv
source .venv/bin/activate   # On Windows use `.venv\Scripts\activate`

# 3. Install Python dependencies
pip install -r rag/requirements.txt
```

### Environment Variables

The application expects the Groq API key to be available as `GROQ_API_KEY`. You can set it permanently in your shell or let the program prompt you on first run.

```bash
export GROQ_API_KEY="your-groq-api-key"
```

---

## Running the Application

```bash
python rag/main.py
```

The script will:
1. Prompt for the Groq API key if it isn’t already set.
2. Download the HR policy document.
3. Chunk, embed, and store the data (only the first run does this; subsequent runs reuse the stored collection).
4. Enter an interactive Q&A loop.

## Configuration

All tunable settings live in `rag/config.py`:

| Variable | Description |
|----------|-------------|
| `GITHUB_RAW_URL` | URL of the raw HR policy text file. |
| `EMBEDDING_MODEL` | Sentence‑Transformer model used for embeddings. |
| `GROQ_MODEL` | Groq LLM model identifier. |
| `COLLECTION_NAME` | Name of the Chroma collection. |
| `CHROMA_PATH` | Directory where the vector store is persisted. |
| `CHUNK_SIZE` | Number of words per chunk (default 50). |
| `SYSTEM_PROMPT` | System‑level instruction that forces the LLM to stay grounded in the supplied context. |

Modify these values if you wish to experiment with different documents, models, or chunk sizes.
